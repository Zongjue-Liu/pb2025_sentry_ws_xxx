## 构建与查看场地

在 Ubuntu / ROS 2 Humble 工作空间执行：

```bash
source /opt/ros/humble/setup.bash
colcon build --symlink-install --packages-up-to pb2025_nav_bringup rmu_gazebo_simulator
source install/setup.bash

ros2 launch rmu_gazebo_simulator gazebo.launch.py \
  world_sdf_path:="$(ros2 pkg prefix --share rmu_gazebo_simulator)/resource/worlds/rmul_2027_3v3_world.sdf"
```

此命令打开场地并桥接仿真时钟。运行后可在 Gazebo 中开始仿真；机器人生成、传感器、导航和决策需要各自的启动入口。

现有 PB 仿真导航入口通过 `world` 拼接地图和 PCD 路径，因此在机器人及传感器话题、TF 配置匹配后，可选择：

```bash
ros2 launch pb2025_nav_bringup rm_navigation_simulation_launch.py \
  world:=rmul_2027_3v3
```

## 使用范围

### 手动切换现有仿真入口

导航与 RViz：`src/pb2025_sentry_nav/pb2025_nav_bringup/launch/rm_navigation_simulation_launch.py` 中 `DeclareLaunchArgument("world", ...)` 的默认值目前为 `rmuc_2025`。启动时传入 `world:=rmul_2027_3v3`，或将该默认值改为 `rmul_2027_3v3`，即可同时选择本目录对应的二维地图 YAML 和更新后的 PCD。`rviz/nav2_default_view.rviz` 通过 ROS 话题显示地图，无需将 PCD/STL 路径写进 RViz 配置。

Gazebo：`src/rmu_gazebo_simulator/rmu_gazebo_simulator/config/gz_world.yaml` 第一行改为 `world: "rmul_2027_3v3"`，`bringup_sim.launch.py` 将加载 `resource/worlds/rmul_2027_3v3_world.sdf`。同时必须在 `robots:` 下添加同级的 `rmul_2027_3v3:` 出生配置；可参考已有 `rmul_2025:` 的字段，重新选择适合新地图的出生位置。否则 `spawn_robots.launch.py` 找不到机器人列表。

完整机器人仿真还需适配以下场景差异，不能仅修改上述两个地图名称：

- 在 `rmul_2027_3v3_world.sdf` 中将 `<world name="rmul_2027_3v3">` 改为 `<world name="default">`，与现有桥接配置及 `set_performer` 服务的 `/world/default/...` 路径一致。文件名和场地模型名仍使用 `rmul_2027_3v3`。
- 参考同目录 `rmul_2025_world.sdf`，补充 `Sensors`（`ogre2`）和 `Imu` 系统插件；当前 2027 场景只加载物理、用户命令和场景广播插件。
- 补齐出生区碰撞地板。保留 PCD 中的地面点不会自动创建 Gazebo 的物理碰撞地面。

在 Linux 仿真工作空间修改源码后重新构建并加载 `install/setup.bash`，再分别启动 `rmu_gazebo_simulator bringup_sim.launch.py` 与上述导航入口。这些配置适配尚未执行，也未做 ROS / Gazebo 运行验证。

本次导入地图、模型和洞口数据，现有默认场地和决策配置保持原值。HNU 折叠机器人、过洞状态机及自主过洞执行链路需要另行集成；洞口先验文件本身不会自动启用过洞。

源项目说明：CAD 外观网格与物理碰撞网格存在差异，出生区地板由其自主仿真运行时额外补充。此处未导入该运行时场景生成器，后续机器人仿真需要处理地板和传感器几何的一致性。

导入时已检查文件内容一致性、地图和点云格式、模型资源引用；尚未在此 Windows 环境运行 ROS / Gazebo 构建或场景验收。
